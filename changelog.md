# Changelog

While the application is in alpha this file describes **how things work now**,
not the order they were built in. An entry that a later change made untrue is
corrected in place rather than left standing with a correction below it.

- Added optional rules: the parts of a game a book offers rather than imposes, declared by the system and decided on by the table. A system lists what it offers and what each one switches on; a room's settings and the Room Config rail carry the switches, and a rule the system marks as required is stated rather than offered, since a switch that cannot move is a lie. A room records only where it has moved a rule, so a system that changes what it offers by default changes it for the rooms that never said otherwise and for none of the ones that did.
- Added tags, the first thing an optional rule switches on. A room that has them on can put words of its own on its characters, its cast, the party's hirelings, and everything in the Library — the table's own words rather than a list anybody publishes, suggested from the tags already in use so a table settles on a vocabulary by using one. The search boxes the cast and the Library already have find by tag as well as by name. A player sees the tags on what they can already see and none of the cast's, and a tag disappears with the thing it was on. Switching the rule off hides them rather than throwing them away. Monolith offers tags and starts with them off; another system may require them, in which case they are simply on.
- Split the game systems out of the application. This repository is the tabletop now and ships no system at all: Cairn, Monolith, and Cities Without Number are repositories of their own, and a server runs whichever systems its admin installed. A new server can do nothing until one is, which makes Management → Systems the first screen a new install needs — it says so rather than showing an empty list.
- An admin installs a system from the catalogue, from any allowed repository, or from a `.devilsystem.zip` as before. The three end in the same place: the same checks, in the same order, on the same files, because arriving over the network buys no trust. Fetching is the only outbound connection the server makes, it will only reach hosts an operator has allowed, and it re-checks that on every redirect rather than once. A system is still data — rules, catalogues, and extracted table JSON, never executable code — and installing one is still atomic, without a restart, with a failure leaving what was there untouched.
- A server comes pointed at a published catalogue, so the menu is there without configuring anything; an operator can point at their own index instead, or at none. Installing from a repository takes the address bar: paste a repository's GitHub page and it is read, and a link to a tag or a commit installs that one rather than the branch.
- A database written when the systems shipped inside the application has its rows corrected on the next start. They recorded those systems as built in, which stopped them ever loading again once the content moved out — so an existing server's rooms come back as soon as their system is installed, rather than staying unopenable.
- Added account tools for the machine the database is on: list the accounts, reset a password, and delete an account that has done nothing. They exist for the one thing the application cannot do for itself — the last admin forgetting their password, which no other admin can then fix. A password is asked for rather than passed as an argument, since an argument is visible to every other process and lands in shell history, and a reset signs that account out everywhere.
- Rules-table results are legible again on every theme. The rows were drawn translucently over the solid colour that separates them, which let that colour through and left the line beneath each result almost invisible on the lighter palettes.
- Quiet text is quiet rather than faint. Three palettes had a muted colour that fell below a readable contrast against their own surfaces — `used` worst of all, and unreadable outright on a rolled result — so each was darkened by the least that fixes it. All six now clear 4.5:1 against their surface, their background, and a rolled result, and muted text is still plainly quieter than body text.
- Systems can be exported, cloned under a new id, retired from new-room choices, restored, and removed once nothing points at them, exactly as before. A system's files and its registry row belong together, and both live with the rest of the server's mutable data so normal backups include them.
- The Devil's Tables now notices a system installed since it started. It runs as a second process against the same database and built its registry once at start, which was harmless while every system was compiled in and would have meant a restart for every install now.
- Published the schema a system is checked against, generated from the one the server validates with and served at `/api/systems/schema`, so a system's author can check their work before pushing it.
- Added linked random tables. Every result row in The Devil's Tables can name a next table from the same set; the link stays in the set's Markdown and its JSON exports, follows a renamed table, and is refused if it points nowhere or forms a loop. In a room the parent lists its possible follow-ups, and one roll automatically rolls the table selected by the result and shows the whole sequence together.
- Repository exports now contain table-set JSON instead of generated Markdown. An admin can export one set or every custom set together; each archive includes a dependency-free Node CLI that compares its JSON with `raw/tables`, lists the sets and individual tables it will add, update, or remove, and requires Y/N confirmation before changing the checked-out repository. Standalone repository sets are registered in `raw/tables/repository-sets.json` and appear read-only in both the editor and game roller after restart.
- Added Help to the rail, above Credits, opening the written guides in their own tab. There are four — player, GM, admin, and The Devil's Tables — and the one matching your account's role opens first, with a picker to read any of the others; they describe what each role can do, which is worth reading whichever role you hold. Each guide is laid out like the rules reference: its pages on the left in the order its own contents lists them, a search across the whole guide above, and the reading beside them. A search says when another guide has answers too. The pages are served from `docs/guide/`, so the guide a reader sees and the guide in the repository are the same files. The table editor's guide stays the single `devils-tables.md` the editor itself serves whole, and is split into pages at its own headings when it is read, so there is still one copy of it.
- Gave an NPC two weapons, and both out of the same pickers a character fills a slot from. Cairn's and Monolith's single Attacks field is now Weapon 1 and Weapon 2, each chosen from the room's weapons — its system's and its own additions, in one alphabetical list — with Custom first for anything the book never priced, which is what the field has always been. The two are filled independently, so one can be picked and the other written in. What was in Attacks is the first weapon, under the key it was already stored as, so nothing already written down moves; the second starts empty. A creature carrying two reaches the rail with two marks, the same pair a character fighting with both hands shows, and either can be rolled. Cities Without Number keeps one, named Dmg, because the rest of that statblock is the book's own Atk/Dmg/Shock row transcribed.
- A creature armed from the pickers carries the entry on the catalogue's own terms, not on a second reading of the line those terms were written from: a weapon that is one by the heading it is filed under rather than by a die in its parenthetical now reaches the rail with its damage, its traits, and its reach, exactly as it would in a character's hand.
- Gave Room Config's Playlists section the album a track came from. The tag reader now reads album and track number as well as artist and title, both are fixed by hand in the same place the other two are, and the room's music is grouped by album in track order by default, with a switch back to one flat list. Music already uploaded is sent back through the reader once for its album, keeping anything a GM has already corrected. Building a running order gained an Add all, an add-the-whole-album beside each group, and drag-and-drop reordering; the up and down arrows stay, since they are the way a keyboard and a phone can both do it.
- Turned the Library's Shown column into a Visible one whose eye is a switch: open means the room can see it, closed means it cannot, and a GM turns it over from the row rather than by selecting the asset and using the bulk bar. The table's rows also alternate shade, so a filename stays with the name above it.
- Gave a room named, ordered playlists, and gave Room Config the section that builds them beside the room's own music. A playlist is a view over the library rather than a gate on it: a track in no playlist is still in the room and still playable, and deleting a track takes it out of every playlist by foreign key rather than by anything remembering to. The room's player gains a picker for which running order it plays through, and advances within that order rather than through everything the room owns; a room with no playlists behaves exactly as it did before. The panel is also where a track's artist and title get fixed when the tag reader read them wrongly. Choosing the playlist stays in the room, with the rest of the transport.
- Gave a room its own gear. Room Config can add items to any list on its system's sheet, take entries out of that room's pickers, and customise one the book priced by copying it and retiring the original in one step. `systems/<id>/items.json` stays the authority for the system and is never written to: a room's additions and retirements are an overlay over it, resolved the same way the catalogue's own merge resolves the rulebook. A room item's id is namespaced with its room, a shape the book's own ids cannot produce, so the two can never collide. Retiring only takes an entry out of the pickers — slots hold plain text, so anything already written on a sheet stays exactly where it is. A hand-typed weapon is read on the same terms the rulebook's are, and the panel shows what it will be read as before it is saved.
- Gave Room Config its Hirelings and Group assets sections, which are one screen because on rows they are the same thing: a roster, a sheet the system defines, a picture, and an order. Both create, duplicate, reorder, and delete, and hirelings can be rolled up from the system's own creation rules. The kinds of shared property a party can own are now declared by the system rather than listed in the panel, so a game that gains a stronghold needs no change here. A save carries the revision it was built from, so a clash says what happened and leaves the edits on the page.
- Moved the group's roster out of the JSON blob it lived in. Hirelings, ships, and what the party owes are rows now, each with an id the database owns and its own sheet, in the shape character records already had. A hireling's picture is a column on it rather than a side table keyed by a string, and an encounter combatant points at a real hireling with a foreign key that cascades — so deleting one takes its combatants with it instead of relying on hand-written cleanup, and a reorder can no longer rename anyone. Editing two hirelings at once is now two saves rather than one document, so two people at the same table stop overwriting each other. Existing rooms migrate on the next start, including the two older shapes real databases still carry: a single ship, and a group's debt as one line of text.
- Gave Room Config its Calendar section, which builds the calendar the room's clock then runs: months, weekdays, and parts of a day are edited as named rows that can be renamed, reordered, added to, and removed, rather than as one comma-separated line, and holidays and recurring events are a table. Where the numbers and the name lists disagree it says so and still saves, because a calendar with an unnamed weekday is workable. When someone else saves first the panel names what they changed and offers a choice between keeping those edits and taking the newer calendar, instead of failing with a message. Advancing the clock stays in the room, where it announces itself to the table.
- Gave Room Config its Library and NPC sections. The Library is a table of the room's maps, scenes, and references with search, multi-selection, and bulk refiling, showing, hiding, and deletion, plus a filter for assets nothing is using. A bulk change checks every asset it names against the room before writing any of them, so a request reaching outside it changes nothing rather than all but one. The NPC section puts the room's cast, the rulebook's bestiary, and a full statblock editor on one screen, and can copy an NPC into another room the same account configures when both run the same system.
- Added Room Config, a GM control panel at an address of its own that opens in a new tab from the rail's Manage section, carrying the room already open or asking which one. It is where a room is set up rather than run, and it adds to the room's own controls rather than replacing any of them. A GM reaches the rooms they are GM of; an admin reaches every room on the server without joining it, appearing in no room's presence and receiving none of its chat; a player reaches none. The sections a room has follow its system and its settings, and one it has switched off is listed with the switch that turns it on.
- Added responsive encounter-map tokens: GMs drag any combatant from the roster onto a map, while players can place and move their own characters and party hirelings. Positions synchronize across the room and stay anchored as the map resizes.
- Made shared music playback an optional room feature that GMs enable from room settings; disabled rooms expose no player, playlist, or audio-file access.
- Added the Production Type room theme, with a deep plum stage palette, amber highlights, and red opposition colour.
- Moved each system's gear out of the rulebook and into `systems/<id>/items.json`, which the application loads instead of reparsing Markdown on every start. The book seeds the catalogue once and has no say in it afterwards: `npm run build:items` fills a catalogue that has none and leaves a filled one alone, so gear that has been corrected, rebalanced, invented, or thrown out stays that way. `--merge` folds in what a book has gained since, still without overwriting an entry or reinstating a retired one. Every item has an id that a reformatted rulebook cannot move.
- Added weapons as a thing the application knows about rather than a name in a slot. An item is a weapon when the book files it under a weapons table or when its own parenthetical states damage, so Monolith's stun gun counts without a die and its sledgehammer counts from under Tools. A weapon carries its damage and the traits the book writes beside it, both read from the rulebook rather than restated. Any slot on a character or a hireling can also be marked a weapon by hand and given damage, traits, and free notes, which is how anything the book never priced gets to be one.
- Replaced the encounter tab's roster with a board the GM chooses: a map from the Library, or zones. The rail already lists who is in the fight, so the tab shows where the fight is instead. A map put here is shown to the table whether or not the Maps tab has revealed it, and putting it here reveals nothing elsewhere.
- Added a weapon selector to characters and hirelings alike: a drop-down over the weapons carried within reach, and a dual-wield toggle that draws a second. A bulky weapon takes both hands, so it can be drawn but never paired. It replaces the free-text weapon a hireling sheet used to carry, and a rolled hireling now starts with their weapon stowed in a slot rather than written in a field.
- Added a colour per side to every theme, so a name in the initiative rail and on the encounter board says whose it is at a glance. Each palette states its own pair rather than one pair being imposed on all of them.
- Added zones to an encounter: named places laid out left to right, with every combatant standing in one or waiting below. Players move their own characters and the GM moves anyone, by dragging a round portrait or by picking it up and choosing where it goes.
- Added what a system's weapon words mean as `systems/<id>/traits.json`, seeded from each book's own definition lists and hand-written where a book explains a word in prose. A weapon's traits now carry their definitions wherever they are shown — beside a slot, in the combat rail, and in the log line of a roll — instead of repeating the word back.
- Added a range to every weapon, read from the notation each system uses: `Melee`, the book's own words for a distance, or `unknown` where a book states none. A slot can record one by hand where its book never did.
- Added shared Freelancer sheets for Monolith and Hireling sheets for Cairn on the Group tab. The GM keeps them and the table reads them, alongside a disabled placeholder for future level-up support.

## 0.1.0 — In development

- Added an optional shared room calendar with custom years, months, weeks, day segments, holidays, recurring events, and GM time advancement.
- Fixed calendar advancement by giving GMs an explicit segments-per-day setting; one advances whole days, while larger values advance one segment per click.
- Added calendar month/year browsing, theme-aware past and partial-day shading, and chat announcements whenever the GM advances time.
- Made calendar advancement respond immediately and synchronize with focused calendar updates instead of reloading the room and chat.
- Added once-per-room easter eggs when the GM first enables the calendar or map notation.
- Added optional persistent map notation with shared drawing, labels, shapes, colors, erasing, undo, and GM clearing tools.
- Moved online and offline presence into the Group party roster and removed the duplicate People panel from the chat rail.
- Moved Rules into the main table tabs with a persistent heading index while retaining the external reference pop-out.
- Added a Monolith character-sheet Vices section with rulebook-backed selection, random selection, and editable custom vices.
- Established the TypeScript workspace and single-process application architecture.
- Added local setup, authentication, rooms, chat, dice, live presence, and room themes.
- Added Cities Without Number as the third compiled-in system, with its character sheet, roll-over saves, 2d6 skill checks, rules, antagonist catalog, and random tables.
- Added system-configurable Group tabs with shared room data, Cairn and Monolith hireling rosters, Monolith group debt, and a responsive starship sheet.
- Added Monolith hull classes to the starship sheet: choosing a size sets its crew, movement, mobility, holds, and starting Starship Scores.
- Added a per-hold part picker offering the book's own starship parts, with bulky parts claiming the hold after them.
- Added roll visibility to the dice roller: anyone can roll privately, which tells the table a roll happened and shows the result to the roller and the GM, and the GM can roll invisibly, which tells the table nothing.
- Added a GM random-table roller: every Cairn, Monolith, and Cities Without Number table read from the system books, type-ahead table selection, a switcher between systems and custom Markdown table sets, and public, private, invisible, or revealed rolls.
- Added d30 table support and corrected Monolith's thirty-result Hollowing table so every outcome can be rolled.
- Added controlled tags for random tables, with fantasy, sci-fi, character-building, random-encounter, and gear filters; every Cairn table is tagged fantasy, every Monolith table is tagged sci-fi, and editable custom-set tags apply to each table in that set.
- Added The Devil's Tables, a second application for writing and curating random tables. It runs on its own port against the same database, starts with or without the game server, and signs in with the same account.
- Added a link to The Devil's Tables in the game's left rail beneath the room list, for admins and GMs. The game checks whether the editor is answering: when it is not, the row says so and offers the command that starts it rather than opening a link that fails. It finds the editor on this host by default, and takes an explicit address for deployments that move it.
- Added a table editor with a grid for rows, columns, and dice, live warnings about values the die cannot reach or does not cover, per-table tags, and a raw Markdown view. An edit rewrites only the table it changed, leaving the rest of the document untouched.
- Added an editable tag vocabulary: tags can be created and renamed by a GM, and merged or retired by an admin, which rewrites every set that uses them. The tags that ship are seeded rather than fixed, so a tag added to the application later appears in its declared place without disturbing one an instance renamed or added itself.
- Added cyberpunk, real-world, world-building, names, and loot to the tags that ship.
- Added CSV import with a downloadable sample, previewed before anything is written, and CSV export of a single table.
- Added zip bundles: an export that carries sets and their tags into another copy of the application, an import that says what it will do before it does it, and a JSON repository bundle with a preview-and-confirm CLI importer.
- Fixed random tables written with a literal pipe inside a cell, which Monolith's injury tables use; they were being read as an extra column.
